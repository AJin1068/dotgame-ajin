### 옵션
**옵션 A (채택): `tick(state, nowMs)` 시간 적분 순수 함수.** 상태에 꽃별 `collectedMs`를 두고, 벌이 도착한 뒤 꽃 칸에 서 있던 ms를 누적한다. 남은 꿀 = 양 − floor(collectedMs/1000).
- 장점: fake clock으로 4999ms/5000ms 같은 경계를 정확히 시험 가능. 프레임 지터에 안 흔들림. canvas와 분리됨.
- 단점: handleKey가 먼저 tick을 불러야 하고(이동 직전까지 채집분 반영), rAF 타임스탬프와 performance.now 불일치를 가드해야 한다. 상태 필드가 늘어난다.

**옵션 B: main.js의 setInterval(1000) 이벤트로 매초 꿀 1 차감.**
- 장점: 구현 코드가 짧다.
- 단점: 로직이 main.js(시계)에 새어 단위 테스트 불가, 꽃에 도착한 시각과 초 경계가 어긋나 "도착 후 정확히 1초" 규칙을 못 지킨다. 결정 동인 1 위반 → 기각.

**결과 표시 옵션** (a) 채택: 화면 전체를 성공=팔레트 1(꿀 노랑)·실패=팔레트 7로 채우고 가운데에 큰 스프라이트(벌/말벌, 1픽셀=8px). 문구 0개, 6장 색만 사용. (b) strings.js에 "성공!/실패!" 문구 배너: AGENTS의 "R2는 새 문구 회피" 기조와 R3 UI 항목 침범 → 기각. (c) 테두리만 번쩍: 헤드리스·사람 모두 인식 어려움 → 기각.

**꽃별 꿀 양 부호화 옵션** (a) 채택: 격자에는 `F`만 쓰고 읽기 순서(위→아래, 같은 줄은 왼→오)로 5·6·7·8·9. 4장의 `F` 기호 유지, 좌표 표 불필요. (b) 격자에 숫자 5~9를 꽃 칸으로 쓰기: 4장 기호 `F`와 어긋남. (c) 좌표 표: AGENTS 위반 → 기각. 불변식: F 개수 = 꿀 목록 길이, 아니면 createState가 throw.

### 2장 이동 규칙 — 표 끝의 "채집·말벌 접촉·소나기·성공 규칙: R2에서 채운다." 한 줄을 아래로 교체

| 항목 | 규칙 | 값 |
|---|---|---|
| 채집 | 벌이 꽃 칸에 도착한 순간부터 그 칸에 서 있는 동안 자동으로 꿀을 모은다. 버튼 없음. 이동 150ms 동안은 도착 전이므로 채집하지 않는다. | 초당 1 꿀 (에이전트 제안) |
| 채집 계산 | 꽃마다 서 있던 시간(ms)을 누적한다. 모은 꿀 = 누적ms ÷ 1000의 내림. 남은 꿀 = 꽃의 양 − 모은 꿀. 누적ms가 양×1000ms에 닿으면 그 꽃은 끝난다. 꽃의 양 5이면 4999ms에 남은 꿀 1, 5000ms에 끝. | 1000ms당 1 (에이전트 제안) |
| 꽃을 떠남 | 꽃을 떠나도 누적은 지워지지 않는다. 다시 와서 이어서 모은다. | 유지 (에이전트 제안) |
| 끝난 꽃 | 끝난 꽃은 화면에서 사라지고 빈 바닥이 된다. 다시 서도 아무 일 없다. | 사라짐 (에이전트 제안) |
| 말벌 접촉 | 벌이 말벌 칸에 도착한 순간(이동 150ms가 끝난 순간) 즉시 실패. 말벌 옆 칸은 안전하다. | 도착 즉시 (에이전트 제안) |
| 말벌 | 말벌은 5장 위치에 고정, 움직이지 않는다. 말벌은 1마리. | 1마리 (에이전트 제안) |
| 성공 | 꽃 5송이의 꿀을 모두 모으면 즉시 성공. | 5송이 전부 |
| 실패 | 말벌 접촉 즉시 실패. (소나기 실패는 R3) | 말벌 접촉 |
| 결과 후 | 성공·실패가 나오면 게임은 멈추고 방향키 입력은 무시한다. 다시 하려면 브라우저 새로고침(F5). | 정지 (에이전트 제안) |

   - `export function tick(state, nowMs)`: status가 playing이 아니거나 nowMs가 유한수가 아니면 state 그대로. lastMs가 null이면 lastMs=nowMs로 기준만 세운다. nowMs <= lastMs이면 같은 state(시계 역행 가드; rAF 타임스탬프와 performance.now 불일치 대비). 아니면 from = max(lastMs, moving?.until ?? 0). 이동 중(nowMs < moving.until)이면 lastMs만 갱신. 도착했으면: 벌 칸이 말벌 칸이면 status="fail". 아니고 끝나지 않은 꽃 칸이면 collectedMs = min(amount*1000, collectedMs + (nowMs − from)). 모든 꽃이 amount*1000이면 status="success". lastMs=nowMs. 불변(새 객체).
   - 보조 순수 함수 `remainingHoney(flower)` = amount − floor(collectedMs/1000) (끝난 꽃은 0), `isDone(flower)`.
   - `handleKey`: ① status≠playing이면 state 그대로, ② 유한수 가드·이동 잠금 버림(기존, 같은 객체 반환), ③ moveBee가 같은 상태면 state 그대로(기존 동일성 시험 유지), ④ 그 외에는 먼저 `tick(state, nowMs)`로 이동 직전까지 채집·접촉을 정산하고 status≠playing이면 그 결과 반환, 아니면 정산된 상태에서 moveBee 후 moving 기록. 이렇게 해야 떠나는 순간까지의 채집분이 옳은 칸에 쌓인다.
   - MOVE_MS 등 R1 상수 변경 없음. 숫자(1000ms/꿀, 5·6·7·8·9)는 모두 기획서 값; 상수 `HONEY_MS = 1000`로 이름만 붙인다.

LEVEL_1_HONEY를 createState에 전달. strings.js 만들지 않음.

## 10. Risks and mitigations
1. R1 e2e 회귀(벌 식별): 꽃·말벌 스프라이트가 팔레트 0~3의 4×4 rect를 써서 기존 식별이 흔들림 → "마지막 50개 4×4 rect" 식별과 그리기 순서 계약(벌은 막대 이전 마지막 스프라이트)으로 해결, 계약을 main.js 주석과 8장에 명시.
2. R1 경로 회귀: 새 맵에서 R1 가장자리 시험 경로가 꽃·말벌을 밟으면 실패/채집이 끼어듦 → 5장 배치 원칙(시작 행·열 비움)과 맵 시험으로 고정.
3. 시계 불일치: rAF 타임스탬프와 performance.now 사이 작은 차이로 tick이 역행 → nowMs<=lastMs 가드와 시험.
4. 떠나는 순간 채집분 손실/오귀속 → handleKey가 tick 후 이동. 시험 포함.
5. 탭이 숨겨졌다 돌아오면 큰 dt가 한 번에 채집될 수 있음 (알려진 한계, 에이전트 제안으로 미해결: 규칙 추가 없이 둔다). 기획서 8장에 한 줄 기록.
6. 막대가 벌 스프라이트 위에 그려져 일부를 가림: 의도(채집 중 보이게). 사람 확인 5·6에서 판독 가능한지 본다.
7. 결과 화면 단색 배경이 스크린샷 게이트에 걸림: 큰 스프라이트가 있어 완전 단색은 아님; 게이트 문제는 리더 소관.
8. 지수/부동소수: ms를 정수로 누적, floor 사용이라 경계 정확. 비정수 nowMs(performance.now 소수)는 허용하되 시험값은 정수.
