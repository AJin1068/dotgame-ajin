## 1. 기준선 (저장소에서 읽은 사실)
- src/logic.js: `createState(rows, honey)`, `tick`, `handleKey`, `moveBee`, `remainingHoney`, `isDone`, `MOVE_MS=150`. 상태: cols, rows, x, y, moving, flowers[{x,y,amount,collectedMs}], wasps, status(playing|success|fail), lastMs. `tick`은 `lastMs===null`이면 lastMs만 정하고, `nowMs<=lastMs`면 같은 객체, 이동 잠금(`nowMs<until`) 중이면 lastMs만 갱신하고 조기 반환한다. 결과 상태에서 tick·handleKey는 같은 객체를 돌려준다.
- src/main.js: 모듈 범위 `state = createState(LEVEL_1, LEVEL_1_HONEY)`. frame: tick → 바닥→꽃→말벌→벌→꿀 막대 → rAF. 결과 화면 480×320 배경 + 패널 80×80 (200,120) + 큰 스프라이트 (208,128), 문구 없음. keydown은 `performance.now()`.
- src/levels.js: `LEVEL_1`, `LEVEL_1_HONEY=[5,6,7,8,9]`. src/strings.js·src/sound.js 없음.
- test/index.js가 logic.test.js·honey.test.js를 import. 기존 13+18 = **31개**.
- e2e/key-sequence.js: 가짜 DOM(ctx는 fillRect만), 벌 식별 = 마지막 50개 4×4 rect, R1 18개 + 기준 5~10 + 기준 11. e2e/chrome-render.js: 정지 화면 한 장, 바닥·음영 bbox 480×320, 막대 행 픽셀 수.
- 걸림돌과 대응: (a) 기존 시험이 `createState(rows, honey)` 2인자 호출 → 소나기는 3번째 인자 옵션, 기본 꺼짐. 기존 "큰 dt(1_000_000ms) 성공" 시험이 깨지면 안 된다. (b) R2 기준 9 "성공 후 방향키 무반응"과 레벨 자동 진행 → 성공 화면 3초 유지, 기준 9에 "레벨 1 성공 후 3초 동안"만 덧붙임(숫자 변경 아님). (c) chrome-render의 바닥 bbox 480×320 검사 → HUD가 맨 아래 줄 바닥·음영(y 314~319)을 덮지 않는다.

## 3. RALPLAN-DR 요약
### 원칙 (5)
1. 기획서가 유일한 기준. 문서를 먼저 고치고 코드는 그 숫자만 옮긴다. 새 숫자는 전부 `(에이전트 제안)` 표시.
2. 규칙은 순수 로직(logic.js)에. 시각은 인자로만. 소나기·레벨 진행·소리 "판정"도 순수 함수, WebAudio·canvas는 main/sound에만.
3. R1·R2 회귀 금지: 기존 31개 시험·e2e R1 18개·R2 기준 5~11 기대값 무변경. 새 기능은 기본 꺼짐 옵션과 새 파일로 붙인다.
4. 문구는 최소(결과 4종 + HUD 1줄), 전부 strings.js 한 곳. 색은 6장 8색만, 새 hex 0.
5. 가장 단순한 선택: 레벨 3개 고정·자동 진행·실패는 F5(=레벨 1부터)·레벨별 설정/난이도/저장 없음.

### 결정 동인 (상위 3)
1. 소나기 경계(89999/90000ms, 마지막 꽃과 동시, 이동 잠금 중, 첫 호출이 handleKey인 경우)를 fake clock으로 결정적으로 시험할 수 있어야 한다.
2. R1·R2 기대값 무변경 + AGENTS.md 금지(터치·반응형·설정·난이도 선택·리더보드·BGM·에디터·랜덤 맵·package.json·8색 외) 준수.
3. 사람이 키와 스톱워치(±0.5초)로 번호별 확인 가능. 레벨 2·3 클리어 경로가 기획서 안에 키 순서로 적혀 있어야 한다(디버그 점프 금지).

### 옵션
**소나기 구현**
- **A (채택)** `createState(rows, honey, stormMs=null)`: 상태에 `stormMs`, `stormAt`(첫 tick 시각 + stormMs), `failReason`. `tick`이 정산 시각을 `min(nowMs, stormAt)`로 자르고, 그 시점에 아직 playing이고 `nowMs>=stormAt`이면 fail(`failReason:"storm"`). 장점: 기존 호출·시험 무변경, 큰 dt에서도 소나기 전에 끝난 꽃은 인정(경계 결정적). 단점: 상태 필드 3개 증가.
- B (기각) main.js에서 `performance.now()`로 판단: 로직 밖이라 시험 불가(동인 1 위반).
- C (기각) 소나기 시간을 `tick` 인자로 매번 전달: 첫 tick 시각 기억이 호출자에게 새 나감.

**레벨 진행**
- **A (채택)** 성공 시 결과 화면 3초(`RESULT_HOLD_MS=3000`, 에이전트 제안) 후 다음 레벨 자동 시작, 레벨 3 성공은 최종 화면에서 정지. 순수 판정 `nextLevelDue`.
- B (기각) 아무 키로 다음 레벨: 기획서에 없는 조작 추가, e2e 기준 9와 충돌.
- C (기각) 레벨 선택·URL 파라미터: 난이도/레벨 선택 금지에 닿음.

**소나기 실패 표시**
- **A (채택)** 배경 팔레트 3(거의 흰색) + 팔레트 0 패널 + 큰 벌 + 문구. 노랑(성공)·주황빨강(말벌)·검정 패널과 모두 뚜렷이 구분.
- B (기각) 말벌 실패와 같은 화면: 이유 구분 불가.
- C (기각) 팔레트 2(#2B2118) 배경: 패널(#1A1A1A)과 거의 구분 안 됨(Arch 지적).

     1. status≠playing 또는 nowMs가 유한하지 않으면 같은 객체.
     2. `lastMs===null` → `{...state, lastMs:nowMs, stormAt: stormMs===null ? null : nowMs+stormMs}` (handleKey가 첫 호출이어도 같은 규칙).
