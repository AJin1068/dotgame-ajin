# R3 계획 — 꿀벌 꿀 모으기 (소나기·레벨 2·3·사운드·UI 문구)

기준: GAME_DESIGN.md (design-v2 커밋 42f3b4e, 파일 머리글은 아직 "v1") @ goal-2 커밋 3934cd7. R1·R2 사람 확인 완료(9장 1~11). 이 문서는 계획이며 코드·기획서를 고치지 않는다. 새 구체값은 모두 `(에이전트 제안)`이며 AGENTS.md에 따라 승인된 값으로 본다. 표시 없는 값은 인터뷰 확정 사실 또는 R1·R2 값이다. R1·R2 숫자와 기존 시험 기대값은 바꾸지 않는다.

## 0. 기준선 (저장소에서 읽은 사실)
- src/logic.js: `createState(rows, honey)`, `tick`, `handleKey`, `moveBee`, `remainingHoney`, `isDone`, `MOVE_MS=150`. 상태 필드: cols, rows, x, y, moving, flowers[{x,y,amount,collectedMs}], wasps, status(playing|success|fail), lastMs. `tick`은 `lastMs===null`이면 lastMs만 정하고, `nowMs<=lastMs`면 같은 상태를 돌려준다. 결과 상태(success/fail)에서 tick·handleKey는 같은 객체를 돌려준다.
- src/main.js: 모듈 범위 `state = createState(LEVEL_1, LEVEL_1_HONEY)`. frame: tick → 바닥→꽃→말벌→벌→꿀 막대 → rAF. 결과 화면: 480×320 배경 + 패널 80×80 (200,120) + 큰 스프라이트 (208,128), 문구 없음. keydown은 `performance.now()`.
- src/levels.js: `LEVEL_1`, `LEVEL_1_HONEY=[5,6,7,8,9]`. src/strings.js, src/sound.js 없음.
- test/index.js가 logic.test.js·honey.test.js를 import. 기존 개수 = 13 + 18 = **31**.
- e2e/key-sequence.js: 가짜 DOM(ctx에 fillRect만 있음), 벌 식별 = 마지막 50개 4×4 rect, R1 18개 검사 + 기준 5~10 + 기준 11. e2e/chrome-render.js: 정지 화면 한 장, 바닥 bbox 480×320, 막대 행 픽셀 수.
- 걸림돌 3개 (계획에 반영): (a) 기존 시험이 `createState(rows, honey)`를 2인자로 부른다 → 소나기는 **세 번째 인자로 켜는 옵션**이어야 하고 기본은 꺼짐. 기존 "큰 dt 한 번이면 성공" 시험(1_000_000ms)이 소나기 때문에 깨지면 안 된다. (b) R2 기준 9 "성공 후 방향키를 눌러도 변하지 않는다"와 레벨 자동 진행이 충돌할 수 있다 → 성공 화면을 3초 유지하고 기준 9 문장에 "레벨 1 성공 후 3초 동안"만 덧붙인다(숫자 변경 아님). e2e 기준 9는 성공 후 +1500ms까지만 보므로 무수정 통과. (c) chrome-render의 "바닥+음영 bbox 480×320" 검사 때문에 HUD가 맨 아래 줄(타일 행 9)의 바닥·음영(y 314~319)을 다 덮으면 안 된다.

## 2. RALPLAN-DR 요약
### 원칙 (5)
1. 기획서가 유일한 기준. 문서를 먼저 고치고 코드는 그 숫자만 옮긴다. 새 숫자는 전부 `(에이전트 제안)` 표시.
2. 규칙은 순수 로직(logic.js)에. 시각은 인자로만 받는다. 소나기·레벨 진행·소리 "판정"도 순수 함수, WebAudio·canvas는 main/sound에만.
3. R1·R2 회귀 금지: 기존 31개 시험 기대값 무변경, e2e R1 18개·R2 기준 5~11 기대값 무변경. 새 기능은 기본 꺼짐 옵션(소나기)과 새 파일로 붙인다.
4. 문구는 최소(결과 4종 + HUD 1줄), 전부 strings.js 한 곳. 색은 6장 8색만, 새 hex 0.
5. 가장 단순한 선택: 레벨은 3개 고정·자동 진행·실패는 F5(=레벨 1부터), 레벨별 설정·난이도·저장 없음.

### 결정 동인 (상위 3)
1. 소나기 경계(89999/90000ms, 마지막 꽃과 동시)를 fake clock으로 결정적으로 시험할 수 있어야 한다.
2. R1·R2 기대값 무변경 + AGENTS.md 금지(터치·반응형·설정·난이도 선택·리더보드·BGM·에디터·랜덤 맵·package.json·8색 외) 준수.
3. 사람이 키와 스톱워치(±0.5초)로 번호별 확인 가능. 레벨 2·3에 도달하는 키 경로가 기획서에 적혀 있어야 한다(디버그 점프 금지).

### 옵션
**소나기 구현**
- **A (채택)** `createState(rows, honey, stormMs=null)`: 상태에 `stormMs`, `stormAt`(첫 tick 시각 + stormMs), `failReason`. `tick`이 정산 시각을 `min(nowMs, stormAt)`로 자르고, 그 시점에 아직 playing이면 `nowMs>=stormAt`일 때 fail(`failReason:"storm"`). 장점: 기존 호출·시험 무변경, 큰 dt에서도 소나기 전에 끝난 꽃은 인정(경계 결정적). 단점: 상태 필드 3개 증가.
- B (기각) main.js에서 `performance.now()`로 소나기를 판단. 로직 밖이라 시험 불가(동인 1 위반).
- C (기각) 소나기 시간을 `tick` 인자로 매번 전달. 첫 tick 시각 기억이 호출자에게 새어 나감.

**레벨 진행**
- A (채택) 성공 시 결과 화면 3초(`RESULT_HOLD_MS=3000`, 에이전트 제안) 후 다음 레벨 자동 시작, 레벨 3 성공은 최종 화면에서 정지. 키 입력·새 상태 없음. 순수 판정 `nextLevelDue(state, nowMs, levelIndex, levelCount)`.
- B (기각) 아무 키로 다음 레벨. 기획서에 없는 조작 추가, e2e 기준 9와 충돌.
- C (기각) 레벨 선택·URL 파라미터. 난이도/레벨 선택 금지에 닿음.

**소나기 실패 표시**
- A (채택) 배경 팔레트 2 + 팔레트 0 패널 + 큰 벌 + 문구. 8색 안에서 말벌 실패(7)·성공(1)과 구분.
- B (기각) 말벌 실패와 같은 화면. 사람이 이유를 못 구분(문구만으로 구분하면 색으로는 구분 안 됨).

## 11. Escalation / Risk Gate
- 같은 확인 항목 2회 연속 X, 한 시도 6회 초과 반복, 범위 밖 기능 필요(예: 레벨 선택, 음소거, 웹폰트) → 중단하고 replan-N, 사람에게 묻지 않는다.
- 사람이 레벨 2·3 경로가 너무 길다고 하면 맵 수정은 기획서 5장 변경이므로 replan 대상(자동 디버그 점프 금지).

- R1·R2 시험·e2e 기대값을 바꿔야만 통과한다면 설계 오류로 보고 중단.

## 12. Risks and mitigations
1. 소나기가 기존 시험을 깸: 옵션 3번째 인자, 기본 null, 시험 1번이 증명, main만 STORM_MS를 넘긴다.
2. 첫 tick 시각 의존: 소나기는 레벨의 첫 tick부터. 새 레벨 상태는 만든 즉시 tick해 맵이 나타나는 순간 시작한다. handleKey가 먼저 불려도 tick이 같은 규칙으로 시작(시험 3번).
3. R2 기준 9와 자동 진행 충돌: 3초 유지, 9장 기준 9에 한 구절 추가, e2e 기준 9는 +1500까지만 보므로 무수정.
4. e2e 벌 식별 깨짐: HUD·문구는 4×4 rect를 쓰지 않고 HUD를 벌 앞에 그린다. 마지막 50개 4×4 = 벌 계약 유지, 계측기가 어기면 throw.
5. HUD가 꽃·막대를 가림: 마지막 줄을 비운 맵 + HUD y 288~313(꿀 막대는 y 타일×32+31까지, 레벨 1 행 8의 막대는 y 287까지). 사람 기준 12에서 확인.
6. chrome-render bbox 깨짐: HUD가 y 314~319를 남김. 새 검사로 확인.
7. 한글 글꼴: 웹폰트 없이 시스템 monospace. 깨져 보이면 사람이 기준 12·13·14에서 발견. 해결(웹폰트 1개 허용 예외)은 replan.
8. 소리 자동재생 정책: 첫 keydown에서 AudioContext 생성. 첫 키 전에는 소리 없음(기준 18에 명시). 소리 없는 환경에서 예외 없이 무음.
9. 숨은 탭: dt 무보정 정책 유지, 소나기 넘기고 돌아오면 즉시 소나기 실패(8장에 명시, 시험 7번).
10. 소나기 동률 해석: "소나기가 오기 전"의 모호함은 동률=성공으로 정함(에이전트 제안, 기획서 2장에 적음).
11. 레벨 2·3 도달 비용(사람이 앞 레벨을 클리어해야 함): 경로와 시간을 기획서에 명시. 디버그 점프는 금지.
12. 소나기 90초가 클리어 경로(43~47초)보다 크게 길어 "시간 압박"이 약함: 값은 승인된 에이전트 제안이며, 압박 조정은 사람이 요구할 때 기획서 먼저.
